# 配役の整理プレビュー

2026-10-16。実DBの2026-10-15保存データを使い、原文と整理案を比較するローカル用ツールを実装した。
公開サイトや本番管理画面のデザイン変更ではなく、[配役仕様案](cast-credit-requirements.md) を実例で確認するための画面。

## できること

- 2,140件の配役を検索・シリーズで絞り込む。まず見る代表例は13件。
- 登録原文と、役名・役ごとの舞台上／声／映像・所属・世代・チーム・参加区分・地域・日時の整理案を比較する。
- 役を追加・削除し、出演形態を複数選択して表示イメージを試す。
- 未確認の補足を原文のまま保持する。整理案を編集しても元の補足を勝手に解決済み扱いにしない。
- 出典URL、確認メモ、整理案への感想を下書き保存し、原文と合わせたJSONを書き出す。
- ブラウザーを再読み込みしても同一データ版の下書きを復元する。ブラウザーが保存を禁止している場合は書き出しを案内する。

「架空の兼役例」は実データと明確に分けた。A役は舞台上、B役は声という構造を試せる。
書き出し時も実データの `records` と架空例の `syntheticExamples` を分離する。

補足を認識できたことは、資料による事実確認の完了を意味しない。

## 起動方法

`next-app` を作業ディレクトリにし、既存の監査スナップショットを指定する。
生成と閲覧にSupabaseの接続情報は不要。本番アプリの起動も不要。

```powershell
npm run preview:casts -- --snapshot-dir=<監査データ保存先> --output-dir=<プレビュー保存先>
npm run preview:casts:serve -- --file=<プレビュー保存先>/index.html --port=8140
```

表示先は `http://127.0.0.1:8140/`。サーバーはループバックだけに接続し、生成した1ファイルだけを返す。
Supabase通信・データ更新API・外部アセットはなく、プレビューからのネットワーク接続はCSPで禁止している。
通常は生成後のHTMLをそのままローカルファイルとして開くこともできるが、下書き保存は同じHTTPの接続先で使う方が安定する。
サーバーを止めても生成済みHTMLは残る。HTMLを再生成した場合は閲覧サーバーを再起動する。

## 次の判断と制限

最初に、代表例の情報の分け方と、編集したときの表示をユーザーと確認する。
その後に本番の保存形式・管理画面・日英表示への変更を一公演ずつ進める。
今回はDBカラム追加、本番への登録、既存データの一括移行は行っていない。

初版の出演条件は一つの条件グループに、全役／特定の一役／未確認という適用先を持つ。
異なる役に複数の別条件がある場合や、複数の上演回への厳密な対応は、保存形式を決める前にモデルを広げる必要がある。
別名と兼役の違い、劇中で演じる役の対応関係も、単なる役名の分割では確定しない。
英訳や共演・出演数の本番集計は、このローカルプレビューでは変更しない。
下書きのJSONは検討用であり、そのまま本番へ投入するための形式ではない。
