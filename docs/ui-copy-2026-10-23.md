# UIコピーの基準と初回整理 — 2026-10-23

言葉を減らすこと自体ではなく、情報の優先順位と操作の目的が伝わることを基準にする。
トップ、About、一覧、詳細、検索、お気に入り、ガイド、問い合わせ、配信一覧を整理した。

## 書き方

- 読点は文の構造や意味を明確にするために使う。短い語句の後に雰囲気で置かない。
  「〜から、」「好きが、」のような呼吸は、必要なら改行や余白で表現する。
- 見出しは内容か行動を短く示す。通常のラベルは句点なし。キャッチコピーの句点は
  言い切りの意図がある場合に残す。本文まで機械的に読点・句点を削らない。
- 「世界が広がる」「より深く楽しむことができます」だけで終えず、出演年表、配役、
  共演者など、実際に見られる情報を書く。
- タイトルやキャストをすぐ下で言い直す導入は省く。データから生成した説明を
  あらすじや作品紹介の代わりにしない。
- ボタンは次の動作を示す。「ステージのつながりを見に行く」より「作品を探す」。
  上限のあるリストは「すべて」と呼ばず、対象と上限を示す。
- 人物の一覧は「俳優」、作品に出演する集団は「キャスト」を基本とする。
- 未登録と不存在を区別する。配信リンクがないことを「配信なし」と言い換えない。
- 英語は日本語の語順や装飾的な読点を持ち込まず、同じ情報を自然に伝える。

## 文字とレイアウト

- キャッチコピーは意味の切れ目で改行する。説明文の短い意味単位には
  `.copy-phrase` を使い、狭い画面で不自然な途中改行が起きにくくする。
- 補足文の `text-wrap: pretty` は段落末の短い取り残しを減らす補助として使う。
  未対応のブラウザでは通常の折り返しを保つ。
- 作品名・俳優名や長いデータ全体に `nowrap` を適用しない。文字サイズを極端に
  下げて説明を詰め込まず、説明の必要性を先に見直す。

## 代表的な変更

| 箇所 | 変更前 | 変更後 |
| --- | --- | --- |
| トップ | 2.5次元舞台の、好きな作品をもっと深く。 | 2.5次元舞台を／もっと深く。 |
| フッター | 好きが、つながる。もっと広がる。 | 好きな俳優から／新しい舞台へ。 |
| About見出し | 舞台の記録を、つながりとして残す。 | 舞台の記録を／つないで／残す。 |
| Aboutボタン | ステージのつながりを見に行く | 作品を探す |
| 検索結果 | 「…」の検索結果：N件を表示 | 「…」の検索結果：N件 |
| 共演者ボタン | すべて見る（上位 N 人） | 共演者を見る（上位N人） |

表の「／」は表示上の改行を表す。ページにはスラッシュを挿入しない。

## 実装の範囲

作品詳細のJP/ENにあったタイトル・主要キャストの再説明を撤去し、未使用の
キャスト要約処理と専用スタイルも削除した。あらすじ、配役、公演日程、出演歴は維持。
FAQの表示文を整理した箇所はFAQPageの構造化データも同時に更新している。
本文から削ったキーワードを見えない場所へ移す処理は追加していない。

俳優プロフィール・作品紹介などDBの登録内容、ガイド本文、料金や視聴条件、
プライバシーポリシーは今回の一括書き換えの対象外。既存のSEOメタデータと
リンク先、検索・投票・お気に入り・配信処理は保っている。

検証記録はタスクのプライベートな `stageconnect-v2-design/copy-local/` と
`copy-production/` に保存。変更前26ページとの比較ではメタデータ、FAQ以外の
構造化データ、リンク、配役・出演歴・あらすじ、プライバシー本文を照合する。
FAQは変更後の表示と構造化データの一致を別に検証する。

ローカルではビルド・型チェック、公開62ページ、既存テスト25件、変更前26ページの
保護対象比較、FAQ17項目の表示一致を確認。Chrome/WebKitで初回24表示・22操作、
最終のAbout・英語フッター12表示、検索エラーからの復帰と投票確認文など2操作を検証した。
投票POSTはブラウザ内でスタブし、検証用の票は本番DBへ保存していない。
実機iPhoneではなくブラウザのスマホエミュレーションを使用している。
