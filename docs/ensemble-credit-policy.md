# アンサンブル・ダンサーの収録方針

2026-10-18、ユーザーから再始動前の運用と、その理由を確認した。個人プロフィールや出演歴が十分に集まらないアンサンブルのために薄い俳優ページを増やさず、作品のクレジットに名前をまとめる。今回新設したページについても、クレジットへの転記と削除の許可を得た。

## 今後の登録

- 役名のない「アンサンブル」「バックダンサー」「あんステダンサー」は、原則`plays.credits`へ保存する。出演者名・区分・原資料の順番・出典を保持する。
- この出演だけを理由に新しい`actors`や`casts`を作らない。生年月日・身長・出身地の空欄を推測で埋め、個人ページを成立させようとしない。
- 個人ページを作る例外は、人物としてのプロフィールや出演歴が十分に確認できる場合に個別判断する。身長などが一つ不明というだけで、役付きの俳優まで登録対象外にはしない。
- 別作品に役付き出演のある既存俳優ページと、その配役は維持する。クレジットへの転記は同じ人物の他の出演事実を削除する理由にはならない。
- 役付き・兼役・声や映像の出演・日替わりゲスト・チーム等の補足は、この方針で一括除外しない。役名なしだけではアンサンブルと断定しない。
- 既存クレジットの名前を配役にも二重登録しない。作品のクレジットは`{ role, names, is_core: false, sort_order }`の既存形式で追記し、制作スタッフ等を保持する。

`buildWorkImportPlan`は該当行を`storageRecommendation: play_credits`として保留し、新規俳優の準備には回さない。`buildWorkCandidateBatch`も、以前作られた準備案からアンサンブル配役を新規保存する操作を停止する。これらは原文を削らずに保存先の確認を促す制御で、クレジットの自動書込み機能ではない。

既存の同一配役に対する`keep`は手入力を守るため維持する。個別の既存データ整理は、変更前後の確認・保存を行った別処理で実施する。DBの汎用RPCの機能やRLSは変更していない。
