# 検索・回遊導線の整備

2026-10-17。新しい公開UIを実際に辿り、検索から作品・俳優・シリーズへ移動する処理を整理した。

## 修正した問題

- 俳優の性別切り替え・ページ移動、シリーズの並び替え・分類・ページ移動で検索語が消えていた。JP/ENともqを維持する。
- 言語切り替えがパスだけを引き継ぎ、検索語・絞り込み・ページ・セクション位置を失っていた。対応する画面の既知の条件とハッシュを引き継ぐ。追跡用パラメーターはコピーしない。
- ヘッダーだけ別の検索処理があり、日本語の候補に英語作品名が表示され、英語のタイトル欄を検索していなかった。既存のsearchSiteを公開候補APIと検索ページから共有する。
- 旧候補リクエストの結果が後から割り込む問題を、キャンセルと結果の破棄で抑止。読み込み・空結果・取得失敗を分け、IME確定時のEnterで送信しない。
- PostgRESTのOR条件へ検索語を直接埋め込んでいたため、括弧・引用符・カンマ等を含む語が文法として解釈され得た。LIKE値のエスケープと文法の引用を分ける。
- 日本語検索ページに入力欄がなかった。JP/EN共通のフォームと結果部品を作り、各分類の一覧へ同じ語で進める。
- 詳細のパンくずが一覧で終わり、一覧部分がリンクにならなかった。現在の作品名・俳優名・シリーズ名を最後に置く。
- 作品詳細のお気に入りボタンに作品名が渡っていなかった。新規保存に正式な表示名・シリーズ名を渡す。既にブラウザへ保存されている旧データは一括書き換えない。
- スマホのメニューの閉鎖時に非表示の操作へフォーカスしないようinertを追加。開閉時のフォーカス、Tab循環、Escape、スクロール復元、低い画面でのメニュー内スクロールを整える。

## データ・構成

- DBスキーマ変更・マイグレーションなし。既存の匿名公開用SupabaseクライアントとRLSを使い、管理者キーを使わない。
- GET `/api/search?q=...` は各分類最大5件の公開情報だけを返す。空検索はDBを呼ばない。検索語は最大200文字、公開応答は短時間キャッシュし、失敗は503・no-storeとする。
- 検索画面は各分類最大20件。全件数の表示とはせず「表示中の件数」として示し、一覧の絞り込みへ進める。
- かな／カナ、全角／半角、名前のスペース・ローマ字URL表記を検索用に扱う。人物同定、登録済みの表記、翻訳辞書は変更しない。
- 新規共通部品: LocaleSwitcher、SiteSearchPage。検索の文字処理はlib/search-query.tsへ集約。

## 検証

- `npm run test:search`: 既存辞書719ルールの保全、言語切り替え、検索正規化・条件文の引用など12テスト。
- `npm run verify:search-api`: 11入力で匿名APIから実DB・応答まで確認。佐藤流司／サトウリュウジ／sato ryuji、英語公演名、A3!、記号入力、5件上限を含む。
- `npm run test:v2-pages`: 42 URL。SEO・配役・投票・旧タグ撤去に加え、絞り込み／ページリンクのq保全、詳細から一覧への戻り道、編集できる検索フォームを確認。
- ブラウザで日英の検索・候補・遷移、モバイルメニュー、お気に入りの保存・表示・解除を確認。保存テストはテスト分だけ解除。
- 本番ビルド、42 URL、11種類のAPI検索、12テストが成功。公開後も同じURL・APIの検証を行う。

参考: [SupabaseのOR条件](https://supabase.com/docs/reference/javascript/or)、[PostgRESTの予約文字](https://docs.postgrest.org/en/stable/references/api/url_grammar.html#reserved-characters)。
